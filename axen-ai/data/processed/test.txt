============================================================
1. WHAT IS A TRANSFORMER?
============================================================

A Transformer is a neural-network architecture based primarily
on attention mechanisms.

Transformers were introduced in the research paper:

"Attention Is All You Need"

The architecture became foundational to modern AI systems,
especially in natural-language processing.

Transformers are now used in:

- Natural language processing
- Large language models
- Computer vision
- Speech
- Audio
- Video
- Multimodal AI
- Protein modeling
- Robotics
- Reinforcement learning
- Time-series modeling
- Recommendation systems
- Code generation

============================================================
2. WHY TRANSFORMERS MATTER
============================================================

Earlier sequence models such as RNNs processed sequences
recursively.

Transformers allow much more parallel processing during training.

They also provide flexible mechanisms for modeling relationships
between distant positions in a sequence.

Important advantages include:

- Parallel training
- Strong sequence modeling
- Scalable architecture
- Flexible attention
- Transfer learning
- Compatibility with large datasets
- Adaptability to many modalities

============================================================
5. SELF-ATTENTION
============================================================

Self-attention allows every token to interact with other tokens
within the permitted context.

The mechanism uses:

Query
Key
Value

For input X:

Q = XWQ

K = XWK

V = XWV

============================================================
6. SCALED DOT-PRODUCT ATTENTION
============================================================

The standard attention equation is:

Attention(Q,K,V)
=
softmax(QKᵀ / √dk)V

where:

Q = Query
K = Key
V = Value
dk = key dimension

============================================================
7. QUERY
============================================================

A Query represents what information a token is looking for.

Queries are produced using a learned projection matrix.

Q = XWQ

============================================================
8. KEY
============================================================

A Key represents information that can be matched against queries.

K = XWK

============================================================
9. VALUE
============================================================

A Value contains the information that is ultimately aggregated.

V = XWV

============================================================
10. ATTENTION WEIGHTS
============================================================

The query-key similarity produces attention scores.

Softmax converts the scores into normalized weights.

The weighted values produce the attention output.

============================================================
11. MULTI-HEAD ATTENTION
============================================================

Transformers commonly use multiple attention heads.

Each head has separate learned projections.

For head i:

head_i =
Attention(Q_i,K_i,V_i)

The heads are concatenated:

Concat(head_1,...,head_h)

and projected using an output matrix.

============================================================
12. ATTENTION HEADS
============================================================

Different attention heads may learn different relationships.

Possible learned patterns include:

- Local relationships
- Syntax
- Long-distance dependencies
- Semantic relationships
- Positional relationships

The exact interpretation of individual heads must be established
through analysis rather than assumed.

============================================================
13. CAUSAL ATTENTION
============================================================

Causal attention prevents a token from attending to future tokens.

For:

A B C D

A can attend to:

A

B can attend to:

A B

C can attend to:

A B C

D can attend to:

A B C D

============================================================
14. CAUSAL MASK
============================================================

A causal mask prevents information leakage from future positions.

This is essential for autoregressive language modeling.

============================================================
15. BIDIRECTIONAL ATTENTION
============================================================

Bidirectional models allow tokens to use information from both
left and right context.

This is useful for representation learning and tasks such as:

- Classification
- Token labeling
- Information extraction

============================================================
16. CROSS-ATTENTION
============================================================

Cross-attention allows one sequence to attend to another sequence.

For example:

Decoder queries
+
Encoder keys and values

This is common in encoder-decoder Transformers.

============================================================
17. ENCODER
============================================================

An encoder transforms an input sequence into contextual
representations.

Encoder-only architectures are useful for:

- Classification
- Retrieval

- Representation learning
- Token classification

============================================================
18. DECODER
============================================================

A decoder generates output sequences.

Decoder-only Transformers are commonly used for autoregressive

============================================================
21. POSITIONAL INFORMATION
============================================================

Self-attention does not inherently encode sequence order.

Transformers therefore require positional information.

Approaches include:

- Learned positional embeddings
- Sinusoidal positional encoding
- Relative positional encoding
- Rotary positional embeddings
- ALiBi
- Other position-aware methods

============================================================
22. SINUSOIDAL POSITIONAL ENCODING
============================================================

The original Transformer architecture used sinusoidal positional
encoding.

It provides deterministic position-dependent values using sine
and cosine functions.

This allows token position to influence representations.

============================================================
23. LEARNED POSITION EMBEDDINGS
============================================================

A learned position embedding assigns a trainable vector to each
position.

Example:

Position 0 → vector
Position 1 → vector
Position 2 → vector

============================================================
24. RELATIVE POSITION
============================================================

Relative position methods represent relationships between token
positions instead of only absolute positions.

This can help models reason about relative distances.

============================================================
25. ROTARY POSITIONAL EMBEDDINGS
============================================================

Rotary positional embeddings, commonly called RoPE, incorporate
position information by rotating query and key representations.

RoPE is widely used in modern decoder-style language models.

============================================================
26. ALiBi
============================================================

ALiBi uses attention biases based on relative token distance.

It can provide useful extrapolation properties for certain
Transformer configurations.

============================================================
27. FEED-FORWARD NETWORK
============================================================

The attention output passes through a position-wise feed-forward
network.

A simplified form is:

FFN(x) =
W2 activation(W1x + b1) + b2

The feed-forward layer provides additional nonlinear
transformation.

============================================================
28. ACTIVATION FUNCTIONS
============================================================

Transformer architectures can use:

- ReLU
- GELU
- SiLU
- SwiGLU
- GeGLU
- Other gated activations

============================================================
29. GATED LINEAR UNITS
============================================================

Gated feed-forward architectures allow one representation to
control another.

Examples include:

- GLU
- GEGLU
- SwiGLU

Gated architectures are common in modern language models.

============================================================
30. RESIDUAL CONNECTIONS
============================================================

Residual connections add the layer input to the layer output.

Example:

output = x + f(x)

They help information and gradients propagate through deep
networks.

============================================================
31. LAYER NORMALIZATION
============================================================

Layer normalization stabilizes activations.

A simplified equation is:

LayerNorm(x)
=
γ((x - μ) / √(σ² + ε)) + β

============================================================
32. PRE-NORM
============================================================

Pre-normalization applies normalization before the main
transformation.

Example:

x = x + Attention(LayerNorm(x))

x = x + FFN(LayerNorm(x))

Pre-norm designs can improve training stability.

============================================================
33. POST-NORM
============================================================

Post-normalization applies normalization after the residual
operation.

The original Transformer architecture used a post-normalization
style.

Modern architectures frequently use pre-normalization variants.

============================================================
34. DROPOUT
============================================================

Dropout randomly removes some activations during training.

It can act as a regularization technique.

Modern large language models may use little or no dropout depending
on architecture and training setup.

============================================================
35. VOCABULARY
============================================================

A Transformer language model uses token IDs.

The vocabulary maps tokens to integer IDs.

The vocabulary can contain:

- Words
- Subwords
- Characters
- Bytes
- Special tokens

============================================================
36. TOKENIZATION
============================================================

Common tokenization techniques include:

- BPE
- Byte-level BPE
- WordPiece
- SentencePiece
- Unigram
- Character tokenization

The tokenizer and model vocabulary must remain compatible.

============================================================
37. EMBEDDING LAYER
============================================================

Token IDs are mapped to dense vectors.

Embedding matrix shape:

[vocabulary_size, hidden_size]

Each token ID selects one embedding vector.

============================================================
38. OUTPUT HEAD
============================================================

For language generation, the final hidden states are projected
into vocabulary logits.

Typical shape:

[batch, sequence, vocabulary_size]

============================================================
39. LOGITS
============================================================

Logits are unnormalized scores for possible output tokens.

Softmax converts logits into probabilities.

The highest probability token can be selected using greedy
decoding, or a sampling strategy can be used.

============================================================
40. AUTOREGRESSIVE GENERATION
============================================================

Decoder-only language models generate one or more tokens
sequentially.

Example:

Prompt:
"AXEN AI is"

Prediction:
"an"

Then:

"AXEN AI is an"

Prediction:
"AI"

The process continues until a stopping condition.

============================================================
41. GREEDY DECODING
============================================================

Greedy decoding selects the highest-probability token at every
step.

It is simple and deterministic but may produce repetitive or
suboptimal sequences.

============================================================
42. TEMPERATURE SAMPLING
============================================================

Temperature modifies the probability distribution before
sampling.

Lower temperature generally makes outputs more deterministic.

Higher temperature generally increases variation.

============================================================
43. TOP-K SAMPLING
============================================================

Top-k sampling restricts candidates to the k highest-probability
tokens before sampling.

============================================================
44. TOP-P SAMPLING
============================================================

Top-p sampling selects a dynamic set of tokens whose cumulative
probability reaches a specified threshold.

============================================================
45. BEAM SEARCH
============================================================

Beam search maintains several candidate sequences during decoding.

It is useful for some sequence-to-sequence tasks.

It is not always preferred for open-ended language generation.

============================================================
46. KEY-VALUE CACHE
============================================================

During autoregressive generation, previously computed key and value
representations can be cached.

This avoids recomputing them for every new token.

This mechanism is called the KV cache.

============================================================
47. PREFILL
============================================================

Prefill processes the initial prompt and builds the model's
internal key-value cache.

After prefill, generation proceeds token by token.

============================================================
48. DECODE PHASE
============================================================

The decode phase generates new tokens using the existing KV cache.

Generation performance is affected by:

- Model size
- Memory bandwidth
- KV cache size
- Attention implementation
- Hardware

============================================================
49. ATTENTION COMPLEXITY
============================================================

Standard self-attention has approximately quadratic complexity
with respect to sequence length.

For sequence length n:

Attention computation is approximately O(n²).

This becomes expensive for very long contexts.

============================================================
50. EFFICIENT ATTENTION
============================================================

Researchers have developed many methods to reduce attention cost.

Examples include:

- Sparse attention
- Local attention
- Sliding-window attention
- Linear attention
- Low-rank attention
- Kernelized attention
- Block-sparse attention

============================================================
51. SLIDING-WINDOW ATTENTION
============================================================

Each token attends primarily to a local window.

This reduces computation compared with full attention for long
sequences.

============================================================
52. SPARSE ATTENTION
============================================================

Sparse attention restricts which positions can attend to which
other positions.

The objective is to reduce unnecessary computation.

============================================================
53. LINEAR ATTENTION
============================================================

Linear-attention methods reformulate attention to reduce its
dependence on sequence length in certain settings.

They may provide efficiency advantages but can have different
quality and capability trade-offs.

============================================================
54. GROUPED-QUERY ATTENTION
============================================================

Grouped-Query Attention, or GQA, uses multiple query heads that
share key/value heads.

This can reduce KV-cache memory and improve inference efficiency.

============================================================
55. MULTI-QUERY ATTENTION
============================================================

Multi-Query Attention uses multiple query heads with shared
key/value projections.

It can significantly reduce KV-cache memory requirements.

============================================================
56. MULTI-HEAD LATENT ATTENTION
============================================================

Some architectures compress key/value information into latent
representations to reduce memory and computation.

The exact implementation depends on the model architecture.

============================================================

150. AXEN TRAINING LOOP
============================================================

2. Tokenize data.
3. Create batches.
4. Move tensors to device.
5. Run forward pass.
6. Calculate loss.
7. Backpropagate.
8. Clip gradients if configured.
9. Update optimizer.
10. Update scheduler if configured.
11. Record metrics.
12. Save checkpoints.
13. Run validation.
